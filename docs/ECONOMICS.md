# AgentCourt AI — Economic Model

## Current status

There is no live token or production economic system in the verified release.

The economic design below is a roadmap, not a claim of deployed functionality.

## Revenue model

### 1. SaaS

- Pro reviewer workspace
- DAO/team plans
- Enterprise evidence operations

### 2. API / infrastructure

Charge agent platforms, marketplaces and protocols for evidence-intelligence API usage.

Potential units:

- case processed
- evidence volume
- API calls
- active organizations
- report generation

### 3. Integration services

Enterprise onboarding, protocol adapters and custom evidence workflows.

### 4. Network fees

Only after the underlying arbitration and settlement system is proven should protocol-level fees be considered.

## Unit economics to measure

The first commercial dashboard should track:

- cases per organization
- evidence items per case
- analysis cost per case
- gross margin per case
- reviewer time saved
- conversion from free to paid
- retention
- API revenue
- partner-sourced cases
- dispute resolution cycle time

## Token policy

A token is **not required for the MVP**.

A future token, if justified, must have a concrete protocol utility rather than exist only as a fundraising mechanism.

Potential future utility could include:

- staking for reviewer eligibility
- dispute-system bonds
- protocol incentives
- delegated governance
- fee discounts

Any token design requires legal, economic and security review before deployment.
